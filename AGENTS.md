# Tweebbo Vita: notes for contributors and AI agents

Read `README.md` and `../Tweebbo-3DS/AGENTS.md`. This is the showcase proof of concept of the
native PlayStation Vita client of Tweebbo; it plays in the same world as `tweebbo.lol`, the 3DS
and the Switch.

- Everything in this repository (code, comments, documentation, interface and commit messages)
  is written in English.
- **Protocol parity**: the protocol must match `../Tweebbo-Vercel/server/src/proto.rs` (version 6,
  `HELLO` with `platform = 1`, capability bits and the trailing device byte `3` = Vita). The s2c
  `DEVICE` (140) message announces each player's native device; older clients ignore it. Keep
  compatibility with `../Tweebbo-3DS` and `../Tweebbo-Switch`.
- **Shared core**: `source/` (except `source/vita/`) is the portable C11 core, identical to the
  Switch client. Keep both copies byte-for-byte equal; fix shared bugs in
  `../Tweebbo-3DS` first when possible. `source/gen/` is generated by `tools/pack.py` of the
  3DS repo: never edit it by hand.
- **Local network only**: this proof of concept never connects to `tweebbo.lol`. `build.sh` bakes
  the hotel of the local network into `DEFAULT_SERVER` and builds with `TWEEBBO_LAN_ONLY`, which
  only accepts private LAN `ws://` addresses. Offline play is an in-game option, not a build.
- **Platform rules**:
  - The canvas is 480×272 (`-DSCREEN_W/-DSCREEN_H`) drawn at 2×; keep whole-number scales.
  - The mirror uses a negative x scale in vita2d (`source/vita/gfx.c`); if a device shows it
    wrong, replace it with a pre-flipped quad without changing the gfx.h contract.
  - Never write settings anywhere except `ux0:data/Tweebbo/`; tokens stay private.
  - Keep `vita2d_wait_rendering_done()` in `gfx_present` and never free a texture during the
    drawing pass: freeing or rewinding what the GPU still reads is a `GPUCRASH` on hardware
    (Vita3K does not show it). Load and free textures only between frames.
  - Every vita2d draw goes through `pool_ok()`: vita2d writes vertices through an unchecked
    pointer when its pool is full.
- **Verification**: `./build.sh` must produce `out/tweebbo.vpk` from a clean tree. The VPK is
  built with `ZIP_STORED` and the furniture inside `romfs/furni.pak` (29 files, quick to install
  in VitaShell); keep it that way unless a measurement says otherwise. There is one build:
  offline play is an in-game option (the connection screen offers it when the hotel does not
  answer; Select toggles it), never a separate package.
  The `sce_sys` / LiveArea images **must be 8-bit indexed PNGs** (`tools/make-sce_sys.py`):
  24-bit ones fail the install with `0x8010113D`. Cross-play check against a local hotel with
  the updated server:
  `TWEEBBO_URL=ws://127.0.0.1:8092 node ../Tweebbo-Vercel/tests/device-announcement.mjs` (the room
  must hear the Switch and the Vita: the server needs the device-byte `current` rule). Visual check:
  `SERVER=ws://127.0.0.1:8092 tools/emu/run.sh` (Vita3K, see README).
- Never log, show or commit player tokens (`token-*.txt`), private codes or production data.
